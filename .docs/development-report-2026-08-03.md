## 一、P0 消息可靠性（命门）

### 1. 离线消息补拉
- **问题**：消息广播是"尽力而为"，对方离线期间的消息直接丢失（仅入房时拉全量历史）。
- **方案**：复用已有的 `HISTORY_REQUEST(room, since)` 协议，补上自动触发：
  - `db.getLatestTimestamp(room)`：本地最新消息时间戳（IndexedDB + localStorage 回退）
  - peer 域重连成功 → `_catchUpLocalRooms()` 对已加入房间补拉
  - useChat 启动后 → 对恢复的"已加入"房间补拉（覆盖刷新场景）
- **验证**：刷新后 joinedNames 恢复 + 补拉路径运行无错。

### 2. 发送确认与重试
- **协议**：新增 `MSG_ACK: 'msg_ack'`（`{ room, msgIds: [...] }`），接收方 500ms 批量汇总回执，减少广播量。
- **状态机**：发送方跟踪 `_pendingAcks`，超时（10s）→ `failed`；收到任一节点 ACK → `sent`。
- **UI**：消息气泡显示 ⏳发送中 / ✓已送达 / ⚠️失败（点击重发）。
- **重发**：`retryMessage` 用**原 msgId + 原 timestamp** 重建消息（签名与原始一致，接收方幂等去重），`buildMessage` 支持显式 id/timestamp。
- **验证**：sending → failed（超时）→ 重发回 sending ✓。ACK 回执需双端新代码（对方强刷后生效）。

### 3. 身份跨设备（P2P 账号迁移）
- **方案**：口令派生的 AES-GCM 加密 JWK 备份文本；恢复时解密写回 localStorage（刷新生效）。
- **入口**：设置面板新增"身份"tab（显示当前 ID、备份口令输入、备份生成/复制、恢复粘贴+口令）。
- **验证**：错口令拒绝 ✓、对口令恢复 ✓。期间修复两个 bug：
  1. `aesGcmDecrypt` 是三参数签名（key, iv, ciphertext），误传对象
  2. 身份存储结构是 `{ priv: JWK(含d/x), pub: 字节数组 }`，校验字段写错

## 二、P1 安全与存储

### 4. 密码房间安全
- **问题**：`JOIN_ROOM` 广播明文密码，信令可监听。
- **方案**：只广播 `passwordHash`（SHA-256），验证方本地哈希比对；`requestJoinRoom` 同样只传哈希。本地明文仅存创建者/已验证成员的 localStorage。
- **验证**：创建密码房间 → 广播无明文、含哈希 ✓。

### 5. 存储管理
- **确认**：聊天消息已走 IndexedDB（`openMessagesDB` + 迁移），localStorage 仅回退。
- **上限设置**：每房间消息条数上限（localStorage `nchat:msg-limit`，默认 5000，0=不限），设置面板可改，改动后立即对全部房间裁剪。
- **自动清理**：`addMessage` 后自动 `trimRoomMessages`（IndexedDB 批量删最旧 + localStorage 回退分支统一同一上限）。
- **数据保留**：屏蔽/过滤仅前端显示层，消息数据完整保留（P2P 冲突安全）。
- **验证**：上限 3 发 5 条 → 库中仅剩最新 3 条 ✓。

### 6. 屏蔽体系（替代房间黑名单）
- **设计结论**：不做房间级踢出黑名单（P2P 下清缓存即新号、维护成本高）；改为：
  - **用户级屏蔽**：成员列表屏蔽按钮（人人可用），其消息不再显示
  - **星级屏蔽**：屏蔽低于 X 星成员的发言（房间设置面板设置）
  - 均为**前端过滤**（`visibleMessages` computed），数据保留；自己消息永不过滤；未知星标不误伤历史
- **验证**：localStorage 持久化读写 ✓、星级设置写入 ✓、过滤逻辑确认。

## 三、P2 体验

### 7. 邀请链接 / 二维码
- **入口重构**：成员列表邀请移除（成员都在房间里，入口不合理）→ **房间列表每房间悬停邀请按钮**。
- **弹窗**（`InviteDialog`）：二维码（`qrcode` 依赖）+ 邀请链接（`?room=xxx`）+ 一键复制。
- **自动加入**：URL 带 `?room=` → init 后自动加入并 `history.replaceState` 清理参数。
- **验证**：QR 渲染 ✓、链接编码 ✓、`?room=` 自动进房 + 历史加载 ✓。

### 8. 打字状态 / 浏览器通知 / 免打扰
- **打字状态**：新增 `TYPING: 'typing'` 协议（发送 2s 节流，接收不转发 gossip），标题栏显示"XX 正在输入…"（3s 自动清除）。
- **消息通知**：他人消息 +（非当前房间 或 页面隐藏）+ 未静音 → 浏览器通知；同房间 tag 合并防堆叠。
- **免打扰**：`nchat:muted` 房间集合，设置面板开关。
- **验证**：免打扰开关持久化 ✓。

### 9. 聊天记录导出
- 房间设置面板"导出聊天记录"→ JSON 文件下载（房间名 + 日期命名）。
- 验证：面板入口存在（下载行为浏览器环境可测）。

### 10. 聊天室级设置面板（`RoomSettingsDialog`）
- 标题栏齿轮按钮**分流**：房间内 → 聊天室级设置；不在房间 → 平台设置。
- 内容：免打扰 / 星级屏蔽 / 屏蔽管理（取消屏蔽）/ 导出记录 / 邀请链接。
- **验证**：四个区块全部渲染 ✓。

## 五、已知限制与后续建议

1. **ACK 双端生效**：送达回执需要所有节点运行新代码（开发阶段，统一部署即可）。
2. **打字状态**：单节点无法端到端目测，广播路径构建/运行无错，建议双开验证。
3. **发送队列（断线排队）**：目前失败仅标记 + 手动重发；后续可做自动重试队列。
4. **消息加密**：密码已哈希化，但消息内容仍明文传播；E2EE 是"对标飞书"宣传的最后一块拼图。
5. **存储容量（字节）**：目前是条数上限；可扩展为字节上限（文件消息占大头）。
